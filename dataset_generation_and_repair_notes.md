# Dataset Generation and Repair Notes

## Purpose

This document records the recovered provenance of the original 168-sample wind-field dataset, the later repair/correction work, and the exact reconstruction procedure used to verify that the recovered generation path is correct. It is meant to serve three purposes:

1. a reproducibility guide that another researcher can follow from scratch,
2. a provenance record for scientific transparency,
3. a source document for later writing the paper's **Methods** and **Data Provenance** sections.

---

## Scope and terminology

This project has two related but distinct dataset histories.

### A. Original 168-sample dataset generation (pre-repair)
This is the historically important path that produced the original large wind TFRecords and the original 168-sample GAN/CNN inference outputs.

### B. Final corrected / repaired dataset pipeline
This is the authoritative path for the paper's final quantitative conclusions. It is the path that should be cited when describing the final results.

These two histories should **both** be documented:
- the **original path** for provenance,
- the **fixed path** for final scientific claims.

---

## High-level dataset provenance summary

The original 168-sample vector dataset was generated by streaming 100 m wind data from NREL's HSDS-hosted WIND Toolkit, extracting a native 500 × 500 Mid-Atlantic patch for 168 consecutive hourly timesteps, converting wind speed and meteorological direction to two-channel `[u, v]` wind components, and generating PhIRE-native `LR->MR` and `MR->HR` TFRecords using PhIRE's own downsampling and TFRecord-writing utilities.

A later internal audit showed that the original MR construction path was flawed, so the final reported results use a corrected dataset-generation pipeline and repaired outputs. The repair/audit history should therefore be documented explicitly, even though the paper itself should stay focused on the final topology result.

# Part I — Original 168-sample dataset generation (pre-repair)

## 1. Upstream data source

The upstream data source for the original 168-sample dataset was the NREL WIND Toolkit national gridded dataset:

- dataset path: `/nrel/wtk-us.h5`
- access method: NREL HSDS (Highly Scalable Data Service)
- Python client: `h5pyd`
- authentication: personal NREL developer API key configured in `~/.hscfg`

Example `~/.hscfg` structure:

```ini
hs_endpoint = https://developer.nrel.gov/api/hsds
hs_username = None
hs_password = None
hs_api_key = <REDACTED>
```

Important provenance note:

- `wtk-us.h5` contains **raw meteorological fields only**.
- It contains **no super-resolution outputs**.
- The SR outputs were generated later by running the pretrained PhIRE GAN/CNN on MR inputs derived from those raw fields.

Pipeline conceptually:

```text
wtk-us.h5  ->  HR / GT (500x500)  ->  [block-average / 5]  ->  MR (100x100)
                                                              |
                                            pretrained PhIRE GAN -> SR_GAN (500x500)
                                            pretrained PhIRE CNN -> SR_CNN (500x500)
```

So `wtk-us.h5` only contributes the **left side** of the pipeline.

## 2. Recovered generation script

The key recovered script is:

- `build_example_data_extension_500.py`

This script is the strongest recovered evidence for the original 168-sample generation path.

### What the script does

The script opens `/nrel/wtk-us.h5` through `h5pyd`, reads grid coordinates, finds the nearest grid point to `(39.5°N, -75.0°W)`, extracts a native `500 x 500` crop around that center, fetches `windspeed_100m` and `winddirection_100m` for `168` consecutive hourly timesteps, converts those fields into two-channel `[u, v]` wind vectors, downsamples them with `utils.downscale_image()`, and writes PhIRE-native TFRecords with `utils.generate_TFRecords()`.

### Recovered operative configuration

- `N_SAMPLES = 168`
- `SAMPLE_INDICES = list(range(168))`
- `HEIGHT = 100`
- `CENTER_LAT = 39.5`
- `CENTER_LON = -75.0`
- `LR_SIZE = 10`
- `MR_SIZE = 100`
- `HR_SIZE = 500`

### Exact spatial interpretation

From the recovered code path and notes:

- nearest grid center: approximately `(39.4998°N, -75.0064°W)`
- native crop rows: `720:1220`
- native crop cols: `2102:2602`
- resulting native patch: `500 x 500`

### Exact temporal interpretation

- time indices: `0..167`
- WTK index `0` corresponds to `2007-01-01 00:00:00`
- WTK index `167` corresponds to `2007-01-07 23:00:00`

So the 168 samples correspond to **one contiguous week of hourly wind fields**.

### Raw variables fetched

Per timestep, the script fetched:

- `windspeed_100m`
- `winddirection_100m`

These were then converted to vector wind components using meteorological convention:

```python
u = -wind_speed * np.sin(theta)
v = -wind_speed * np.cos(theta)
```

This produced the two-channel representation `[u, v]` expected by the PhIRE wind pipeline.

### Resulting tensor hierarchy

- HR stack: `(168, 500, 500, 2)`
- MR stack: `downscale_image(HR, 5)` -> `(168, 100, 100, 2)`
- LR stack: `downscale_image(MR, 10)` -> `(168, 10, 10, 2)`

### Output TFRecords

The script writes:

- `example_data_extension_500/wind_LR-MR.tfrecord`
- `example_data_extension_500/wind_MR-HR.tfrecord`

using `utils.generate_TFRecords()` in native PhIRE schema.

### Important caveat about stale comments

Some comments and printed text in the script still refer to "5 samples" and output shapes like `(5, 100, 100, 2)`. These appear to be stale remnants of the original shipped-example clone template. The **operative configuration** in the script is clearly `N_SAMPLES = 168`, and the actual generated arrays/logs confirm 168 samples.

## 3. One-sentence paper provenance summary

A concise paper-ready statement is:

> The 168 samples were extracted from the NREL WIND Toolkit national dataset (`/nrel/wtk-us.h5`, accessed via the HSDS API), selecting `windspeed_100m` and `winddirection_100m` at a native 500 × 500 grid crop centered on 39.5°N, 75.0°W for 168 consecutive hourly timesteps beginning 2007-01-01 00:00 UTC, converted to zonal and meridional wind components `[u, v]`, and downsampled to MR (100 × 100) and LR (10 × 10) resolutions using PhIRE's block-averaging operator.

## 4. Relationship to Stengel et al. (2020)

The pretrained PhIRE GAN and CNN weights used in this project come from the official PhIRE release associated with Stengel et al. (2020). However, the evaluation dataset used here is not the same as the one used in that original paper.

### Similarities

- same PhIRE pretrained GAN/CNN weights,
- same `[u, v]` wind representation,
- same hub height (`100 m`),
- same two-stage SR scale factors:
  - `10x` for `LR -> MR`
  - `5x` for `MR -> HR`

### Differences

- this project uses the HSDS-accessible national WTK dataset `/nrel/wtk-us.h5`,
- the original paper used a different regional/time setup and direct-download WTK handling,
- this work generated its own evaluation dataset and ran inference only,
- no retraining was performed for the current study.
